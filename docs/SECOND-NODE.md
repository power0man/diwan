# الجهاز الثاني (Acer Nitro) — مقترحُ دورٍ ينتظر قرار المالك

> **مقترح لا قرار.** كُتب في الجلسة السحابية ٢١ سبتمبر ٢٠٢٦ لأن اتفاقًا
> سابقًا على «تفعيل الايسر عقدةً ثانية» جرى في محادثةٍ ولم يُكتب، فلم يجده
> بحثٌ في المستودع كله ولا في سجل الجلسة السحابية. وهذا أول سقوطٍ فعليّ
> لقاعدة «الذاكرة ملفّات المستودع لا محادثة» — فالقيد هنا يمنع تكراره.

### القياس (ع٢، ٢٦ سبتمبر ٢٠٢٦)

قيس على الجهاز نفسه بجلسة Claude Code (`anthropic/claude-opus-5-5`)، ونُقل الناتجُ حرفيًّا:

```
$ nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv
name, memory.total [MiB], driver_version
NVIDIA GeForce RTX 4060 Laptop GPU, 8188 MiB, 610.62
```

| البند | الناتج |
|---|---|
| نظام التشغيل | Windows 11 Home ‏10.0.26200.7623 (x86_64) |
| WSL2 | **موجود**: WSL 2.9.13.0، النواة 6.18.40.1-1؛ التوزيعتان `Ubuntu` (الافتراضية) و`docker-desktop`، كلتاهما الإصدار 2 |
| Ollama | 0.34.4 — بلا نموذجٍ مسحوب (`ollama list` فارغ) |
| Docker | Docker version 29.8.0, build 88096ef — المحرّك يجيب (`29.8.0 linux`) |
| git | 2.52.0.windows.1 |
| Python | 3.12.9 |
| uv | 0.12.19 |

**حدود هذا القياس:**
- Ollama وDocker وWSL2 وPython وuv ثُبّتت على الجهاز في اليوم نفسه بطلب المالك في الجلسة، قبل هذا القياس. فالناتج وصفٌ لحال الجهاز بعد التثبيت، لا لحاله الأصلية.
- إصدار التعريف قيس `577.00` قبل التثبيت و`610.62` بعده. والسبب لم يُحدَّد.
- فحصُ الدخان (`tools/launch_check.py`) **لم يُشغَّل** في هذا القياس، وشُغّل بعده (القسم التالي).
- 8 غ.ب من ذاكرة البطاقة تعني، بنصّ الوظيفة الرابعة أدناه، أن فرضية طبقة ‎27B **تُختبر على الماك لا على هذا الجهاز**.

### فحص الدخان (ع٢، ٢٦ سبتمبر ٢٠٢٦)

شُغّل على Windows 11 الأصلي (لا داخل WSL2)، ببايثون 3.12.9، وعلى `main` عند `71b3e63`.

```
$ uv run --no-sync python tools/launch_check.py
  ✗ runtime: import_failed — ModuleNotFoundError: No module named 'fcntl'

✗ عطب: يُصلَح قبل الإطلاق.
```

**رمز الخروج: `1`** (`failed`). فشرطُ «يخرج 0» في تعريف إنجاز #21 **لم يتحقّق**.

| الخطوة | النتيجة | السبب |
|---|---|---|
| runtime | سقط `import_failed` | `core/seal.py` يستورد `fcntl`، وهي وحدةٌ لا توجد على ويندوز. وتستوردها **أربعَ عشرةَ وحدةً** خارج الاختبارات (عُدّت بعد الدمج؛ كان المكتوب هنا سبعًا): `core/seal.py` و`core/router.py` و`agent/actions.py` و`agent/journal.py` و`conversation/session.py` و`conversation/agent_session.py` و`tools/publish_projection.py` و`ci/run_persistent_runner.py` و`evaluation/acceptance_store.py` و`evaluation/capabilities.py` و`webui/server.py` و`workspace_tools/backup.py` و`workspace_tools/files.py` و`workspace_tools/preferences.py` |
| morphology، engine، agent_turn، policies، ui | لم تُشغَّل | الفحصُ يتوقّف عند أول عطب |

**حدود هذا الفحص:**
- `--no-sync` لأن `uv run` يثبّت الاعتماديات قبل التشغيل، والتكليف «لا تثبّت شيئًا». فالبيئة `.venv` جزئية من `uv sync` أُوقف قبل تمامه. لكن السقوط في استيرادٍ من المكتبة القياسية، فلا تغيّره بيئةٌ كاملة.
- عطبٌ ثانٍ ظهر أثناء الفحص: الإخراجُ النصّي نفسُه ينهار على طرفية ويندوز (`UnicodeEncodeError` بترميز `cp1256` عند الحرف `✗`) قبل أن يطبع سطرًا. والسطرُ أعلاه من تشغيلٍ بـ`PYTHONIOENCODING=utf-8`، أما `--json` فيعمل بلا ضبط. **وأُصلح بعده:** تسقط العلاماتُ إلى ASCII (+ وo وx) حين لا يكتبها ترميزُ الطرفية، ويُستبدل ما بقي بدل أن ينهار الفحص.
- الطريقُ إلى 0 على هذا الجهاز: إمّا ج٧ (`core/filelock.py` بدل `fcntl`، وهي تعتمد على ع٢)، وإمّا التشغيلُ داخل WSL2. وحتى حينها تتوقّع النسخةُ العامة بلا متونٍ الرمزَ `3` في خطوة السياسات.

### فحص الدخان داخل WSL2 (ع٢، ٢٦ سبتمبر ٢٠٢٦)

شُغّل في نسخةٍ مستقلّة من المستودع داخل WSL2 (Ubuntu 26.04.1)، على `main` عند `b893715`، ببايثون النظام 3.14.4. وOllama على ويندوز يُبلغ من WSL بضبط `networkingMode=mirrored`، والمحرّكُ `qwen3.5:9b` مسحوب.

```
$ python3 tools/launch_check.py
  ✓ runtime: runtime_ready_public — بايثون 3.14.4، نسخةٌ public
  ◻ morphology: camel_missing — CAMeL Tools غيرُ مركَّب — `uv sync` ثم `uv run camel_data -i morphology-db-msa-r13`
  ✓ engine: engine_ready — qwen3.5:9b على http://127.0.0.1:11434
  ✓ agent_turn: agent_turn_live — 2 خطوات، والجواب: يحتوي الملف notes.txt على عبارة: "مرحبًا بديوان على هذا الجهاز".
  ◻ policies: corpus_missing — المتنُ غيرُ موضوع محليًّا — `python tools/place_private_stores.py --from ~/diwan-private`
  ✓ ui: ui_ready — tools/serve_ui.py يُهيَّأ

◻ تعذّر بحدٍّ معلن: أكمل ما سُمّي أعلاه ثم أعد الفحص.
```

**رمز الخروج: `3`** (`unavailable_declared`) في أربعة تشغيلاتٍ من خمسة. لكن شرط الإغلاق («3 وكلُّ ما قبل السياسات ok») **لم يتحقّق**، لأن `morphology` قبلها ليست ok.

| الخطوة | النتيجة | السبب |
|---|---|---|
| runtime | نجح | — |
| morphology | تعذّر `camel_missing` | CAMeL Tools يحتاج بيئة المشروع، و`uv sync --extra dev` يسقط هنا: `editdistance` (عبر camel-tools) بلا عجلةٍ لبايثون 3.14، ولا مترجم C على الجهاز. وتثبيتُ `build-essential` يحتاج `sudo` بكلمة مرور |
| engine | نجح | `qwen3.5:9b` حيّ |
| agent_turn | نجح حيًّا في ٤ من ٥ | التشغيلُ الأول سقط `agent_turn_failed` (`http_500`): خادمُ النموذج في Ollama انهار عند أول تحميل (`0xc0000409`، تجاوزُ مخزنٍ في المكدّس) بعد ٢٣ ثانية، ثم نجحت التشغيلاتُ الأربعة التالية |
| policies | تعذّر `corpus_missing` | النسخةُ العامة بلا متون، كما هو متوقَّع |
| ui | نجح | — |

**حدود هذا الفحص:**
- بايثون النظام لا بيئةُ المشروع، فالفحص لا يشهد لإصدارات الاعتماديات المقفولة.
- انهيارُ Ollama الأول لم يُشخَّص، ولم يتكرّر في أربع محاولاتٍ بعده. فهو حادثةٌ واحدة مسجّلة، ولا يُعرف بعدُ أعابرةٌ هي أم تتكرّر عند كل تحميلٍ بارد.
- الطريقُ إلى إغلاق #21: مترجم C داخل WSL (`sudo apt install build-essential` بيد المالك)، ثم `uv sync --extra dev` و`uv run camel_data -i morphology-db-msa-r13`، ثم إعادةُ الفحص.

لقياس البطاقة، على الايسر في PowerShell:

```powershell

```

## الدور المقترح: عقدةُ شهادةٍ مستقلة — لا عقدةَ استدلال

**لا يُجعل الايسر عقدة استدلال الآن**، ولو كانت بطاقته كبيرة. فالخطة
المعتمدة اليوم (ق٤١) أوقفت التوسع قبل القياس، وعدّت إضافة عقدةٍ ثالثة
قبل قياس الأوليين خرقًا لثلاث قواعد. وإضافةُ عقدةِ عتادٍ جديدة قبل م١٤
هي الخطأ نفسه بصورةٍ أعرض. **القدرة تُقاس أولًا، ثم تُوسَّع.**

وأمّا الدور الذي لا يضيف قدرةً بل يضيف **صلابةَ دليل**، فهو مطلوبٌ الآن
لأنّ حاجته أُثبتت بعيبين في يومين — كلاهما من عائلة «شرطٌ رمّز جهاز
المالك»:

- `cd36397` — عتبة المسح السلبي رمّزت الماك فأسقطت الاستنساخ الطازج.
- `tools/install_hooks.py:127` — `startswith("3.14.")` يُسقط ٨ اختبارات على
  أيّ بايثون آخر، ويناقض ق٢ الذي أبقى `>=3.11` عمدًا.

والسببُ البنيويّ واحد: **كلُّ دليلٍ يُنتَج ويُعاد إنتاجه على بيئةٍ واحدة**.
كشفُهما جاء بالمصادفة من بيئةٍ سحابية مختلفة، والمصادفة ليست ضمانة.

### ثلاث وظائف تصلح عند أيّ بطاقة، والرام تكفيها بسعة

1. **مُشغِّل CI ثانٍ (x86_64)** — وظيفةٌ موازية تُعيد إنتاج الفحوص على
   معمارية ونظام وبايثون مختلفة. وسمُ CI الحالي
   `[self-hosted, Linux, ARM64, diwan-isolated]`، فيلزم وسمٌ ثانٍ ووظيفة
   ثانية لا تعديلُ القائم. أيُّ افتراضٍ محليٍّ يسقط فورًا لا بعد أسبوع.
2. **شاهدُ مراسٍ مستقل** — التواقيع صارت Ed25519 عامةً تُتحقَّق **بلا سرّ**
   (تحقَّقت الجلسة السحابية منها على استنساخ طازج: ٧/٧). فجهازٌ ثانٍ
   يتحقق دوريًّا ويحفظ المراسي **يُغلق حدَّ ق٢١ المعلن**: «من يعيد كتابة
   الختم مع السجل معًا خارج الكشف» — لأنّ الاثنين لم يبقيا في يدٍ واحدة.
3. **عقدة تضمينٍ وفهرسة** — `bge-m3` حجمه ‎1.2 غ.ب، يعمل مرتاحًا على بطاقةٍ
   صغيرة، فتُزاح أعباء الفهرسة عن الماك المشغول بالاستدلال والواجهة.

### ووظيفةٌ رابعة مؤجَّلة بشرطها

قياسُ نموذجٍ من طبقة ‎27B (ما تعدّه الصناعة اليوم حدًّا أدنى لوكيلٍ محليّ
جادّ، عند ‎٢٤ غ.ب ذاكرةِ بطاقة) — **بعد م١٤ لا قبله**، ولأنّ فرضية «فجوة
جودتنا فجوةُ حجمٍ لا تصميم» تستحق اختبارًا. وشرطُها الأول رقمُ البطاقة
أعلاه؛ فإن كانت ٨ غ.ب أو أقلّ فالفرضية تُختبر على الماك لا عليه.

## حدودٌ تسري على الجهاز الثاني كما تسري على الأول

نطاقه مستودع `diwan` وحده · لا حذف ولا `push --force` · لا أسرار في
المستودع · ولا يُسجَّل مُشغِّلٌ عليه قبل أن يُقال للمالك صريحًا: **ما يُدفع
إلى هذا المستودع يصير قابلًا للتنفيذ على هذا الجهاز**، ويوافق.
