# توسعة فريق الوكلاء والمراحل — ٧ أكتوبر ٢٠٢٦

**تكليف المالك:** «قدم المراحل واضف kimi و جمناي كوين ديب سيك كل ماهو متاح سواء كان محلي او سحابي».
**إضافة المالك:** «ايضا انتي جرافتي».
**سياسة الاختيار التي اختارها:** «أفضل وكيل متاح بحسب المهمة».
المسألة #356. التوسعة داخل `team/`، وتوثيقها واختباراتها؛ لا تغيّر محرّك ديوان أو نواته.

## الوجهة والمراحل

| المرحلة | العمل والمخرج | الحالة وبوابة الانتقال |
|---|---|---|
| ٠ — خط الأساس | تسجيل تدخل المالك، والزمن، وإعادة العمل، والعيوب الهاربة بالطريقة السابقة | ملف ٦ أكتوبر منشور؛ قياس استرجاعي على ٤٠ طلبًا، مع حدود معلنة |
| ١ — دورة التكليف | إرسال، وعامل واحد، وطلب، وفحوص، ومراجع مستقل، وسجل أدلة | التنفيذ الأساسي مدموج في #344 و#347 |
| ٢ — التجربة الموجّهة | عشر مهام، مع تسجيل التوقف والحصة وإعادة العمل | غير مكتملة؛ السجل في جولة ٧ أكتوبر يحتوي قبولًا للمهمتين #345 و#285؛ لا حكم نجاح للبوابة بعد |
| ٣ — توسيع الوكلاء | اكتشاف الأدوات والنماذج المحلية والسحابية، وعائلة النموذج، ودوره وحدوده؛ وربط Gemini وOpenCode وAntigravity | قُدّمت الآن بتكليف المالك أعلاه؛ #356 يقدّم التنفيذ، والقبول الحي لكل محوّل مستقل |
| ٤ — اختيار بحسب المهمة | تقييم الوكلاء على مهام ممثلة بالمواد والشروط نفسها، ثم اختيار أفضل مرشح له دليل حديث | السياسة منفذة؛ لا ترتيب جودة مخترع قبل وصول أدلة التقييم |
| ٥ — قياس الحجم | ٣٠–٥٠ مهمة؛ مقارنة السلامة والتدخل والزمن والكلفة والجودة | بعد مراجعة تجربة المرحلة ٢ وقبول المحوّلات المستخدمة؛ لا توازٍ داخل المهمة |
| ٦ — الاستخراج | فصل النظام إلى مستودع مستقل، وديوان أول محوّل مشروع | الاسم والرخصة بقرار المالك بعد الإثبات |
| ٧ — التعميم | محوّلات للبحث العلمي والبحث التنظيمي وIMO ومشروعات المالك | بعد الاستخراج؛ هذا الطلب لا ينشئ عقدًا في ديوان |

تقديم مرحلة الوكلاء لا يعلن أن تجربة المرحلة ٢ اجتازت بوابتها. يجب توحيد تعريف الزمن قبل المقارنة: خط الأساس يحسب
من فتح الطلب إلى الدمج؛ والسجل التجريبي الحالي يسجل أيضًا الزمن من إذن المالك. وتظل بوابات السلامة والجودة نافذة.

## ما يُضاف وكيف يعمل

| الطريق | الوكلاء أو النماذج | الدور والحد |
|---|---|---|
| عامل CLI | Claude وCodex وGemini | كتابة داخل نسخة عمل بتكليف مأذون؛ الطبيب يفحص الأداة قبل الإطلاق؛ ربط Gemini لا يثبت عزلًا أو نجاحًا حيًا |
| عامل Antigravity | أداة `agy` مع نموذج صريح من `agy models` | قد تشغّل Gemini أو Claude أو GPT-OSS؛ العائلة للنموذج لا للأداة؛ `--sandbox` قيود طرفية، و`accept-edits` للعمل و`plan` للمراجعة؛ خرج JSON يحتاج دخانًا حيًا قبل التثبيت |
| عامل OpenCode | أي `provider/model` صريح معروف العائلة | لا يرث النموذج الافتراضي ولا عائلته ضمنيًا؛ بلا `--auto`؛ أذون الأدوات ليست صندوق عملية؛ عائلة غير مسجلة في مشروع ديوان تُرفض قبل الإرسال |
| مشارك نصي عبر Ollama | Qwen وDeepSeek وGemma وLlama وJais وGPT-OSS وMistral وMiniMax وMiniCPM، وما يُكتشف لاحقًا | التخطيط والاستدلال والعربية والصياغة والمراجعة الاستشارية؛ مدخل صريح فقط؛ لا أدوات ولا قراءة تلقائية للمستودع ولا تنفيذ لناتج النموذج |
| Kimi عبر Ollama | النماذج التي تبدأ بـ`kimi` | التأليف المستقل والصياغة؛ لا سياق آلي للمستودع ولا دور حكم على شيفرته |
| Kimi Code | الأداة المثبتة تظهر في الجرد | مؤلف البنك مستقل؛ تشغيله يبقى عبر `tools/kimi_drive.sh` خارج المستودع؛ لا يُستبدل بمحّول عامل يقرأ شيفرة ديوان |
| Hermes | أداة الباحث المثبتة | باحث خارج المستودع وفق ق١٧ و`docs/HERMES-RESEARCH.md`؛ الجرد يعلن وجوده ولا يطلق جلسة بحث ولا يمنحه الكتابة أو المراجعة المحتسبة |
| نماذج التضمين | BGE وQwen Embedding وNomic، إن وُجدت | تُدرج في المستبعدات بسببها؛ ليست وكلاء محادثة |

«كل المتاح» يعني اكتشاف الموجود والمضبوط على الجهاز، لا سحب أوزان جديدة ولا شراء اشتراك ولا إنشاء مفاتيح. فشل
قراءة تعريف نموذج لا يُعرض نجاحًا؛ يُكتب بسبب مسمى. ووجود وسم سحابي محلي لا يثبت الدخول أو الحصة أو صحة الاستجابة.
مزوّد OpenCode أو Ollama لا يغيّر العائلة: GPT-OSS من openai، وGemma من google، وQwen من qwen، وKimi من moonshot.

## التوجيه والتقييم

`select` يقارن الأدلة الخاصة بنوع المهمة، لا عدد المعاملات أو أسماء البائعين. كل سجل تقييم يحمل:
`agent` و`identity` و`role` و`score` (٠–١٠٠) و`source` و`at` و`status`.

- تُربط هوية نموذج Ollama ببصمته في `/api/tags`؛ وتغييرها يُبطل الدليل القديم.
- لا يُقبل دليل أقدم من ٣٠ يومًا أو مؤرخ في المستقبل أو بلا مرجع أو حالة نجاح، ولا أرقام NaN أو خارج النطاق.
- لا يُختار مراجع مجهول العائلة أو من عائلة مؤلف المادة. وهذه مراجعة استشارية؛ سياسة مشروع ديوان ق٧٥ مستقلة عنها.
- تسجيل الدرجة فعل المقيم؛ النظام لا يستنتجها من مديح الوكيل لنفسه. المرجع إقرار تشغيلي، وليس شهادة تحقق من محتواه.
- المسار النصي الآلي يرشّح الطرق المسموحة أولًا؛ بلا `--allow-cloud` يختار أفضل محلي مقاس، ومراجعة `auto` تشترط `--author-family`.
- قبل التقييم لا اختيار آلي: النتيجة `no_measured_candidate`، وللتجربة الأولى يُختار الوكيل صراحةً.
- «الأفضل» هو الأفضل بين الأدلة المسجلة لذلك النوع، ولا يثبت الأفضلية العامة أو توافر حصة سحابية الآن.
- آخر عطب للمشارك النصي خلال ٣٠ دقيقة يحجبه من الاختيار الآلي؛ تغيّر هوية النموذج يمنع نقل العطب إليه. نجاح سابق لا يثبت الحصة الآن.
- هويات أدوات CLI دون نموذج صريح لا تثبت إصدار النموذج السحابي؛ أدلتها تحتاج إعادة تقييم عند تغيّر إعداداته.
- تُحفظ حالة التشغيل والتقييم في `~/.diwan-team/`؛ نتيجة النقل المجهولة لا يعاد طلبها تلقائيًا.

## أوامر الاستخدام

من نسخة العمل التي تحتوي هذا الطلب، بمفسّر البيئة المكتملة:

```sh
python -m team.agents list
python -m team.agents select --role arabic
python -m team.agents select --role review --author-family openai

# خطة بلا توليد ولا كتابة حالة
python -m team.agents ask --agent ollama:qwen3.5:9b --role reasoning

# المدخل نص صريح على stdin؛ المخرج في موطن الفريق، لا في المستودع
printf 'أجب بالرقم وحده: ٢ + ٢' | python -m team.agents ask --agent ollama:qwen3.5:9b --role reasoning --execute

# المسار السحابي معلن؛ لا تُرسل ملفات المالك الخاصة فيه
python -m team.agents ask --agent ollama:deepseek-v4.1-flash:cloud --role reasoning --allow-cloud

# بعد تقييم خارجي فعلي: source مرجعه، والدرجة نتيجة ذلك التقييم
python -m team.agents record --agent ollama:qwen3.5:9b --role arabic --score 80 --source 'تقييم-المالك-مثال'
python -m team.agents ask --agent auto --role arabic
python -m team.agents ask --agent auto --role review --author-family openai

DIWAN_TEAM_ANTIGRAVITY_MODEL=gemini-3.1-pro-high python -m team.dispatch run 356 --worker antigravity
python -m team.dispatch run 356 --worker gemini
python -m team.dispatch run 356 --worker auto
DIWAN_TEAM_OPENCODE_MODEL=ollama/gpt-oss:20b python -m team.dispatch run 356 --worker opencode
```

الدرجة ٨٠ في المثال ليست نتيجة منشورة ولا تُسجّل أثناء إعداد هذا الطلب. استخدام `--execute` إرسال فعلي؛ الاختيار لا يمنح
إنفاقًا جديدًا. لا تُغيّر تثبيتات الطبيب بـ`--pin` إلا بعد دخان ناجح للأدوات المقصودة. أمر الطبيب الافتراضي صار يشمل
محوّلات العمال الخمسة، فلا تسقط تثبيتات Claude وCodex عند إضافة البقية.

## المراجعة والحدود

لقطة الجرد الحي [`agents-inventory-20261007.json`](agents-inventory-20261007.json): ٧ أدوات CLI و١٤ نموذج محادثة
عبر Ollama؛ ثلاث أدوات تضمين مستبعدة، واسم DeepSeek قديم يردّ HTTP 410. طلب حسابي محلي مع `qwen2.5:3b`
أكمل وأجاب ٤ (بصيغة الرقم العريض `４`). هذه ليست مقارنة جودة؛ لم تُنفَّذ طلبات توليد سحابية أو دخان للعمال الجدد.

يبقى جدول ق٧٥ المحتسب كما هو: Codex لعمل anthropic، وClaude لعمل openai، وClaude أو Codex لعمل google.
Gemini وOpenCode وAntigravity الجديدة لا يصبحان مراجعين محتسبين بمجرد الربط، ولا تستبدل نتيجة مشاركة نصية قبول طلب دمج.
العزل يعتمد على الأداة الأصلية؛ OpenCode بلا صندوق عملية مضاف؛ وقراءة Codex للقرص ليست محصورة في نسخة العمل.
قيمة الدولار المدخلة لا تُنفذ سقفًا في Gemini وOpenCode وAntigravity أو Ollama، وهذه الطرق لا تعلن أن السقف متحقق.

هذا الطلب مبني على `main` ولا ينسخ إضافة `revise` غير المدموجة في #349. تُراجع ملاءمة التغييرات عند دمج الطلبين.

## المصادر الأولية للربط

- واجهة Ollama: [chat](https://docs.ollama.com/api/chat)، و`/api/tags` و`/api/show` من الخدمة المحلية.
- Gemini: [المخرجات غير التفاعلية](https://geminicli.com/docs/cli/headless/) و`gemini --help` المثبت.
- OpenCode V2: [الأوامر](https://opencode.ai/v2/docs/cli/commands/) و[الأذون](https://opencode.ai/v2/docs/permissions/)
  و`opencode run --help`؛ لا تُستخدم أسماء إعدادات V1 مع V2.

- Antigravity: `agy --help` و`agy models` من الأداة المثبتة؛ فحص `team.doctor` اللاحق أظهر 1.3.1؛ القائمة الحية أظهرت عائلات google وanthropic وopenai. لا تُعتبر قائمة النماذج إثبات توليد أو حصة.

فحص الطبيب بلا `--pin` أظهر Claude وCodex مطابقين لتثبيتهما، وGemini وOpenCode وAntigravity غير مثبتة؛ لم يُعدّل ملف الطبيب.

فحص الأدوات الإضافية وجد Hermes، ولم يجد `aider` أو `cursor-agent` أو `agent` أو `amp` أو `goose` أو `copilot` أو `jules` على PATH؛ لم يثبّت أدوات جديدة.
