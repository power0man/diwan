# `team/` — حاضنةُ نظام تعاون الوكلاء (ق٧٦)

**ما هذا:** مرسِلٌ تسلسليّ صغير يُخرج المالكَ من دور الناقل بين الوكلاء: مسألةٌ أذن بها المالك ← تكليفٌ مودَع ببصمة ← نسخةُ عملٍ
وفرع ← عاملٌ واحد ← طلبُ دمج ← فحوص ← مراجعٌ مستقلّ من عائلةٍ أخرى ← المالك يدمج بيده. كلُّ تحوّلٍ قيدٌ في سجلٍّ مسلسل بالبصمة.

**ما ليس:** ليس جزءًا من منتج ديوان ولا من حلقته الوكيلة ولا عقدةً معرفية. **حاضنةٌ تجريبية قابلةٌ للاستخراج:** ديوان مختبرُها
الأول لا حدودُها، وبعد إثباتها تُستخرج منصّةً مستقلة يصير ديوان أول محوِّل مشروعٍ فيها. حدُّها الأضعف في `docs/TEAM-BOUNDARY.md`.

## الحالات

`dispatched` (تكليفٌ مودَع ببصمة) ← `claimed` (معرّفُ العملية وبدؤها) ← `completed` (رأسُ إيداعٍ وطلبٌ مفتوح) ← `validated`
(الفحوصُ خضراء على ذلك الرأس) ← `verified` (مراجعٌ مستقلّ على الرأس نفسه) ← `accepted` (إيداعُ الدمج على `main` من git).
الشرط: `validated_head_sha == reviewed_head_sha == merge_candidate_head_sha`؛ وإيداعٌ جديد يُسقط ما قبله إلى `completed`.
الجانبية: `outcome_unknown` (**لا يُعاد التشغيل**)، `validation_failed`، `expired`، `worker_unavailable:<code>`،
`reviewer_unavailable:<code>`، `brief_stale`، `frozen_by_launch_plan`، `already_dispatched`، `review_uncalibrated`،
`reviewed_awaiting_validation`، `review_rejected` (مراجعةٌ رافضة لا تصير `verified` أبدًا، والأحدثُ على الرأس يطغى)، `external_review`
(طلبٌ لم يفتحه الفريق، أو طلبُ محاولةٍ سابقة بعد استحواذ: يُقيَّد على محاولته ولا يمسّ الجارية)، `takeover`.
السجلُّ (`~/.diwan-team/dispatch.jsonl`) يُفتح ويُلحَق تحت قفلٍ حصريّ على `dispatch.jsonl.lock`؛ فأمران متزامنان لا يكسران السلسلة.
و`resume` يستعيد إطلاقًا انقطع عنه المرسِل قبل قيد `claimed` إن شهد له ملفُّ معرّف العملية؛ وإلا قيّد `outcome_unknown` بسبب
`launch_unconfirmed` ولم يُعِد التشغيل؛ ويفسّر المخرجاتِ بمحوِّل العامل المسجَّل في `dispatched` لا بمحوِّل سطر الأوامر.
و`gc --yes` لا يحذف نسخةَ عملٍ مدموجٍ طلبُها إن كانت محاولتُها جاريةً في السجلّ، أو فيها تعديلٌ غير محفوظ، أو ملفٌّ متجاهَل في git
ليس مخبأَ تشغيل (`.env`، `var/`…)، أو إيداعٌ ليس على `origin/main`؛ ويُعرض سببُ التخطّي والمتجاهَلُ المعنيّ.
و`takeover` يُثبت الغياب إمّا بمعرّفِ وكيلٍ معروف لم يعد حيًّا، وإمّا بأن الإطلاقَ لم يقع أصلًا (لا معرّفَ ولا مخرجَ وقد فحصه
`resume`؛ والغلافُ `team/adapters/_wrap.py` يحفظ معرّفَ الوكيل قبل أن يأذن له بالتنفيذ، فمن مات غلافُه قبل الكتابة خرج بلا تنفيذ)؛ وملفُّ خروجٍ فارغ أو غيرُ رقميّ `outcome_unknown` لا صفرٌ.

## حدودٌ معلَنة (دحض ٦ أكتوبر ٢٠٢٦)

- قفلُ السجلّ يمنع تداخلَ الكتّاب لا الانهيار: موتُ عمليةٍ بين القيد ومرساته يترك ذيلًا بلا مرساة؛ والقرّاءُ بلا قفلٍ مشترك.
- `pid_alive` فحصُ وجودٍ لا هويّة: معرّفٌ أُعيد استعماله يُقرأ حيًّا.
- `run` و`resume` على المحاولة نفسِها في اللحظة نفسِها قد يتسابقان على قيد `claimed`؛ والمالكُ يشغّلهما يدًا واحدةً بالتتابع.
- القياداتُ الجانبية (`reviewer_unavailable`) تُنسب إلى المحاولة الجارية ولو كان الطلبُ المراجَع لمحاولةٍ سابقة.
- طلبٌ دُمج ضغطًا أو إعادةَ أساس يبقى عند `gc` «ليس على main» فلا يُحذف؛ الاتجاهُ الآمن.
- `takeover` يكتب علامةَ `taken_over` قبل فحص الغياب ويزيلها إن رُفض؛ غلافٌ بلغ فحصَ العلامة في تلك اللحظة يُجهض إطلاقَه (125) بلا تنفيذٍ ثانٍ، وهو الاتجاهُ الآمن.

## التشغيل

```
python3 -m team.doctor --pin                                    # مرّةً بعد دخانٍ ناجح
python3 -m team.dispatch run <issue> --worker claude            # خطةٌ بلا أثر
python3 -m team.dispatch run <issue> --worker claude --execute  # إرسالٌ فعلي
python3 -m team.review <pr> --execute                           # مراجعةٌ مستقلّة وتعليق
python3 -m team.dispatch validate <issue>; python3 -m team.dispatch accept <issue>
```
الموطن: `~/.diwan-team/` (السجلّ، والتثبيتات، والمعايرة، والمخرجات الخام). نسخُ العمل تحت `~/diwan-work/wt/team-<issue>-<family>`.

## تسليم Codex بإيداع من المنسق (#361)

يظل صندوق العامل كما هو. الخطة لا تكتب السجل أو الفهرس، ولا تسحب من الشبكة. الأمر الثاني فعل صريح يتطلب
أسماء الملفات نفسها وبصمتي الخطة والفرق المعروضتين، وهو إيداع محلي فقط:

```sh
python3 -m team.dispatch handoff 338 --file tools/example.py --file tests/test_example.py --controller-agent anthropic/claude-fable-5-1
python3 -m team.dispatch handoff 338 --file tools/example.py --file tests/test_example.py --controller-agent anthropic/claude-fable-5-1 --execute --expected-plan-sha256 <plan_sha256> --expected-diff-sha256 <diff_sha256>
```

الأسماء في المثال تُستبدل بالأسماء الفعلية بعد فحص المصدر؛ القائمة ليست شهادة أمان للشيفرة. `diff_sha256` يبصم الرأس
ومحتوى الملفات وأنماطها وهوية ملفاتها، و`plan_sha256` يربط معها هوية المحاولة والمشروع والفرع والتكليف والمخرجات والفهرس والسجل.
تُرفض تغييرات غير مسماة، وفهرس مرحّل سابقًا، وأي انجراف قبل الخطة أو أثناء إعداد الإيداع. يبقى brief المولد غير مودع.
مخابئ تشغيل Python والاختبارات غير المتتبعة تبقى خارج الإيداع والفحص؛ أما أي ملف متتبع فيُعامل مصدرًا مهما كان اسم مجلده.
الملفات العادية العامة وحدها: لا حذف ولا وصلات رمزية/صلبة ولا ملفات خاصة أو مخازن المالك أو محجوب أو أسرار معروفة.
المحوّل يفحص أيضًا أنماط البيانات الشخصية والمفاتيح؛ لا يفتح مخازن المالك ولا المحجوب لبناء بصمات منها.
هذه فحوص مسارات وأنماط، وليست إثباتًا دلاليًا بأن نصًا عامًا لا يحتوي مادة خاصة منسوخة أو شيفرة خبيثة؛ يلزم فحص الفرق.

يلزم آخر قيد `validation_failed:no_commits` على المحاولة الجارية نفسها، مع نجاح العامل المسجل، ورمز خروج محفوظ صفرًا،
ومخرج JSONL قابل للقراءة فيه `turn.completed`، وآخر رسالة، ومعرّف عامل معلوم غائب وكل غلاف معلوم غائب. جلسة حية أو
تعذر فحص tmux أو خروج ناقص أو نتيجة مجهولة أو خدمة غير متاحة أو محاولة مستحوذ عليها رفض مسمى. تثبت نسخة العمل
بتسجيل Git، والرأس برأس الفشل وأصل التكليف؛ سجلات المرحلة الأولى القديمة تعتمد أيضًا اشتراك نسخة العمل المسجلة في
Git مع مستودع المنسق. السجلات الجديدة تضيف اسم محول المشروع ومسار بيانات Git المشتركة، بلا إعادة كتابة القديم.

يسجل المنسق `controller_commit_started` قبل تحريك الرأس، ثم `controller_commit` بدليل الإيداع وبصمات الملفات.
يبقى `claimed` آخر حالة رئيسة، ولا تتغير مدة الإيجار. يحمل الإيداع `Diwan-Agent` للمنسق و`Team-Source-Agent: openai/codex`
بوصفه نسبة مصدر غير مصادقة، وبصمتي الخطة والفرق؛ ولا يدعي أن العامل أودعه بنفسه. تحتسب أدوات المراجعة عائلتي المصدر
والمنسق ضمن المؤلفين؛ لا تضاف أهلية لمراجع. إذا جمع الإيداع anthropic وopenai بقي المالك طريق المراجعة المحتسبة وفق السياسة القائمة.

بعد الإيداع يشغّل المنسق قائمة فحوص المضيف الكاملة في `AGENTS.md` على الرأس المعاد، ويثبت أن الرأس لم يتغير أثناءها،
ثم ينفذ `resume <issue> --host-checks-passed <head_sha>` منفصلًا. `resume` بلا هذا الإعلان بعد إيصال `controller_commit` يعيد
`awaiting_host_checks` برأس الإيصال ولا يدفع. الرأس المعلَن هو رأس نسخة العمل الحالي، وهو رأس الإيصال أو إيداعٌ بعده: فحصٌ يكتب
(`--write`) فغيّر ملفًا أو أنشأه يُودَع ما ولّده بإيداعٍ مستقل وتُعاد الفحوص على رأسه، لأن نسخة العمل تُشترط نظيفة (سوى ملف التكليف
غير المتتبَّع). الرفض المسمّى: `host_checks_head_mismatch` لرأسٍ غير رأس نسخة العمل، و`host_checks_head_not_after_handoff`
لرأسٍ لا ينحدر من الإيصال، و`host_checks_worktree_dirty` لنسخةٍ غير نظيفة، و`host_checks_without_controller_commit` بلا إيصال.
يُقيَّد الإعلان `host_checks_declared` إقرارًا من المشغّل غير مصادق (`declaration_authenticated: false`)، ولا يثبت أن الفحوص جرت.
والدفع تحت قفل السجل يشترط آخر إعلانٍ بعد الإيصال على الرأس الذي يُدفع نفسه، ونسخةً نظيفة: فإيداعٌ لاحق يعطي
`outcome_unknown:host_checks_not_declared`، وتعديلٌ غير مودَع `outcome_unknown:worktree_dirty_after_host_checks`.
الإيداع نفسه لا يشغل push أو PR أو validate أو merge، ولا يسجل accepted أو calibration.
الفحوص المحلية لا تصير قبولًا أو تجربة تسليم مستقلة؛ تُحسب هذه الحالة `controller-assisted` وتدخلها تدخل فعلي.

إذا انقطع التنفيذ بعد قيد النية، يمنع `handoff` التكرار ويعيد `resume` الحالة `outcome_unknown:controller_commit_incomplete`؛
يفحص المنسق الرأس والفهرس والنية يدويًا ولا يحذف الدليل ولا يعيد الإطلاق. قفل الفهرس يمنع أوامر Git المتعاونة من تغيير
الفهرس/تبديل نسخة العمل أثناء الإعداد، وCAS يمنع استبدال رأس متقدم. لا يعزل ذلك كاتبًا خارجيًا يتجاهل الأقفال؛ البايتات
المودعة هي اللقطة المفحوصة، وأي كتابة بعد آخر فحص تبقى عملًا غير مودع. لا تشغل العملية مرشحات Git أو خطافاته من
نسخة العامل؛ لذلك فحوص المضيف والمراجعة اللاحقة لازمتان. هذه العملية ليست توسيعًا لصلاحيات العامل.

## ما يُؤجَّل صراحةً

**تحديث ٧ أكتوبر ٢٠٢٦:** أمر المالك بتقديم مرحلة الوكلاء وإضافة المتاح محليًا وسحابيًا؛ التنفيذ والسياسة والمراحل في
[`AGENTS-PLAN-20261007.md`](AGENTS-PLAN-20261007.md). أضيف جرد `team.catalog` وأوامر `team.agents` ومحوّلات Gemini وOpenCode وAntigravity؛
ظهور نموذج في الجرد لا يشهد بنجاحه أو استحقاقه للمراجعة المحتسبة. التجربة الموجّهة ما زالت غير مكتملة.

القائمة التالية هي ما كان مؤجلًا قبل ذلك التكليف؛ ما لم تتناوله التوسعة يبقى مؤجلًا:

`plan.py`، `report.py`، محوِّلا Gemini وOpenCode، التوازي داخل المهمة، أيُّ ناقل رسائل (CCCC، hcom، ACP)، أيُّ لوحة، أيُّ مكتبة بحث.

## جسر إنهاء OpenCode 2.x

بعض ردود `run --format json` في 2.0.14 تصل بلا `step_finish` رغم اكتمالها. يشغّل المحوّل الآن جلسة خاصة في قاعدة
مؤقتة، ثم يصدرها بـ`session export --standalone` ويطابق الجلسة والمجلد والنموذج والوكيل والطلب والنص وبصمته،
وحالة `succeeded` وسبب الإنهاء `stop`. النص أو رمز الخروج صفر وحدهما لا يكفيان. لا يمس قاعدة الخدمة القائمة.

المسار محدود بجولة نصية واحدة بلا أدوات؛ الرد المبتور، أو المتداخل، أو الخاطئ، أو المحتوي على أدوات يبقى غير مقبول.
`DIWAN_TEAM_OPENCODE_MODEL` إلزامي بمعرّف مزوّد/نموذج معروف العائلة. ويمكن تعيين
`DIWAN_TEAM_OPENCODE_AGENT` لاسم وكيل نصي صريح معدّ في OpenCode؛ وإلا تبقى أسماء `build` و`plan` الأصلية.
انتهاء مهلة المراجعة يوقف مجموعة عمليات الجسر وخادمه الخاص. هذا دليل اكتمال للنقل، لا قبول لجودة الجواب أو
منح دور تطوير عام أو مراجعة محتسبة. لا تتغير إعدادات الخدمة أو حساباتها أو معايرة الفريق.
