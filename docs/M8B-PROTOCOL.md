# م٨-ب — بروتوكول القبول المستقل والمراجعة البشرية

**٢١ سبتمبر ٢٠٢٦؛ ق٢٨.** بُنيت آلية المراجعة وحفظ المحاولات. البنك
المستقل والحكم البشري لم يوردا بعد؛ مرحلة م٨-ب لم تُغلق؛ بدأ بناء م٩ التجريبي وفق ق٢٩.

## استقلال البنك

الخمسة عشر بندًا في م٨-أ علنية، وتبقى تطويرية بعد مراجعتها. أي حالات
يؤلفها وكيل داخل جلسة التطوير وتنكشف حلولها له تُعامل بالطريقة نفسها؛
فصل الوكلاء لا يصنع حجبًا عن سياق التطوير.

يعد المراجع البشري بنكًا جديدًا بعد تثبيت نسخة المرشح وإعداداته، ويحفظ
مراجعه خارج سياق المطور. لا يلصق الحلول في محادثة التطوير ولا يرسلها
في رسائل النموذج الجاري اختباره. يبدأ بخمس حالات على الأقل؛ ويوسع
التغطية قبل تعميم النتيجة على العربية أو المهام العامة.
إذا انكشف حل، يسجل الكشف وتنتقل الحالة إلى التطوير قبل عرض المرجع.
إعادة تسميتها أو إعادة ترتيبها لا يعيدان استقلالها.

هوية المؤلف وتاريخ إعداد البنك وإقراره بالاستقلال معلومات يوردها
البشر، وليست حقيقة تثبتها بصمة الملف. ضوابط التطبيق لا تمنع مالك
حساب الجهاز من قراءة الملفات؛ العزل القوي يحتاج بيئة منفصلة (ق٩).

## التثبيت قبل المحاولة

يسجل ملف خطة محلي ثابت العناصر التالية:

| العنصر | المطلوب |
|---|---|
| المرشح | نسخة الشيفرة، بصمة أوزان المزود المتحقق منها، سياسة البيانات وإعدادات الطلب والنظام |
| البنك | بصمة كاملة تشمل المهام والمراجع والمعايير، هوية المؤلف وتاريخها وإقرار الاستقلال |
| الميزانية | سقف النداءات والإخراج والمال والمهلة قبل التنفيذ؛ لا تعديل تبعًا للنتيجة |
| المحاولات | حد ثابت معلن؛ يبدأ من محاولتين كحد أقصى في البروتوكول الأول |
| الكشف | حد تجميع لا يقل عن خمسة، ولا تجميع انتقائي قبل حكم جميع الحالات الحية |
| معيار القبول | صحة المعنى، اكتمال الطلب، أمانة النسبة، اللغة، وغياب خطأ جوهري؛ لا تعويض خطأ المعنى بدرجة الأسلوب |
| المقارنة | الشواهد نفسها أولًا، ثم المخزن نفسه عند بناء المسار المركب؛ نفس المزود والإعدادات وسقف الموارد |

`candidate_sha256` في واجهة التخزين بصمة وصف المرشح المثبت أعلاه،
ولا تكفي تسمية نموذج متغيرة. تغيير البنك أو المرشح أو سياسة المحاولات
في مخزن قائم يُرفض؛ إنشاء مخزن جديد ليس استئنافًا للمحاولة السابقة
ولا وسيلة مصرحًا بها لزيادة حدها.

## ما تفرضه آلية المحاولات

`evaluation/acceptance_store.py` يثبت البيان وحالة واحدة ذرية تحت قفل.
تُخصم المحاولة وتحفظ قبل إعادة رمزها. استئناف الرمز المفتوح يحفظ
العدد والدرجات، والرمز الجديد لا يتجاوز محاولة مفتوحة أو سقفًا نافدًا.
الدرجات من نوع bool صريح، وتكرار الدرجة نفسها آمن؛ تغييرها يرفض.

المرجع والمعيار لا يدخلان `visible_tasks`. التجميع يقبل حقولًا عددية
محددة، ويرفض إخراج نتائج فردية أو مراجع أو حقول زائدة، ويحفظ الإغلاق
قبل إعادة الملخص. الكشف يحفظ هوية الكاشف وسببه والنقل الدائم أولًا.
التجميع التاريخي يظل لقطة لوقت إغلاقه ولا يعاد حسابه بعد الكشف.

هذه واجهة تخزين للمقيّم؛ استدعاء `record` لا يثبت بنفسه أن إنسانًا
حكم أو أن نموذجًا نودي. ربط عامل تشغيل البنك المستقل وأجوبته الفعلية
بأحكامه جزء باقٍ عند ورود البنك، ولا يصف هذا القبول المصطنع تلك
الوَصلة بأنها منجزة. لا يختبئ نموذج حَكَم في أي جزء مبني.

**حد الثقة:** الملف المبصوم يكشف التلف والتناقضات المفحوصة، ولا يمنع
مالك القرص من إعادة كتابة الحالة والبصمة معًا أو إرجاع نسخة قديمة
أو نسخ مخزن جديد. ليست هذه مرساة مضادة للتراجع خارج حساب المستخدم.

## مراجعة الأجوبة العامة الحالية

`tools/review_capabilities.py prepare` ينشئ HTML عربيًا محليًا بلا شبكة،
يعرض المهمة والجواب والمرجع والمعايير. يبدأ كل حكم فارغًا. يسجل
المراجع `pass/fail/unsure` والسبب ودرجة الخطأ ووقت المراجعة، ثم يصدّر
JSON مع إقرار شخصي. لا تملأ أداة أو وكيل هذا الإقرار بدل الإنسان.

```sh
.venv/bin/python tools/review_capabilities.py prepare --report "$DIWAN_REPORT" --suite evaluation/suites/arabic_general_v1.json --output-dir "$DIWAN_REVIEW_DIR"
.venv/bin/python tools/review_capabilities.py import --report "$DIWAN_REPORT" --review "$DIWAN_HUMAN_REVIEW"
```

المخرج داخل `var/reviews/`، ويجب استعمال **ملف التقرير نفسه** عند
الاستيراد، حتى لو كان تقرير آخر يعيد الأجوبة نفسها. القرار يرتبط
ببصمة كامل التقرير والإعداد والبنك وكل جواب؛ لا تقبل قرارًا قديمًا
بعد تغيير المخرج. ملفات التشغيل والمراجعات خارج git.

الاستيراد يتحقق ويطبع ملخصًا ولا يغير التقرير الخام. رمز خروج 0
يعني صلاحية ملف القرار؛ `judgment` قد يكون failed أو unresolved أو
incomplete. لا يعلن passed إلا مراجعة جميع الحالات واجتيازها، وتظل
`release_ready=false`. الهوية إقرار محلي غير مصادق عليه، والبصمات
ربط للملفات لا توقيعًا يثبت أصلها.

مراجعة بنك م٨-أ تفيد تشخيص العيوب، لكنها لا تحول البنك العلني إلى
قبول مستقل. وبالمثل نجاح اختبارات المراجعة والمحاولات لا يعد حكمًا
بشريًا على إجابات النموذج.

## ما يغلق المرحلة وما يليها

تُغلق م٨-ب عند اكتمال الآلية المراجعة، وورود بنك مستقل مؤرخ بعد تثبيت
المرشح، وتشغيل خط البداية وحفظ أثر المحاولات والكشف، وورود أثر الحكم
البشري وتوثيق نتائجه ومعالجة موانع صلاحية القياس. لا يشترط أن يبلغ
المزود الجودة النهائية قبل بناء تحسيناته؛ إخفاق قدرته يسجل كما هو.
لا يدعى نجاح جودة الأجوبة قبل الحكم البشري. التنفيذ الحالي ينجز
تجهيز الآلية فقط، ويرفق حزمة مراجعة فعلية للتشخيص العلني.

بعد أمر المالك بالاستمرار، ق٢٩ يفصل بناء م٩ التجريبي عن اعتماد
جودة المساعد: يستمر العمل التقني دون إغلاق م٨-ب أو اختلاق حكم بشري.
بوابة قبول الجودة أعلاه باقية؛ نجاح pytest يثبت اختبارات المكوّن
فقط. يوضح `M9-ACCEPTANCE.md` ما نُفذ وحدود الدليل.
