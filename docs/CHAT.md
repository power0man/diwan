# تشغيل المحادثة المحلية التجريبية — م٩

محادثة نصية متعددة الجولات من الطرفية. تحمل الأجوبة صفة `unverified`:
لم تمر بتحقق المصادر، ولا تُدخل تلقائيًا إلى مخزن المعرفة أو التفضيلات.
القبول البشري المستقل في م٨ ما زال معلقًا؛ هذه أداة تجربة محلية.

## البدء والاستئناف

عيّن `DIWAN_CHAT_MODEL` لهوية النموذج المثبت محليًا، و`DIWAN_CHAT_DIGEST`
لبصمة SHA-256 الكاملة المقابلة في بيانات Ollama المحلية. لا يحتاج
ذلك إلى شراء أو تنزيل نموذج. يجب أن يكون خادم Ollama القائم متاحًا
عند `127.0.0.1:11434`، وألا يحمل النموذج بيانات تنفيذ بعيد.

```sh
.venv/bin/python tools/chat.py --session daily chat
```

أعد الأمر نفسه لاستئناف الجلسة. الإعدادات ثابتة داخل الجلسة؛ تغيير
النموذج أو بصمته أو الحدود يحتاج معرف جلسة جديدًا. `/history` يعرض
السجل و`/exit` يخرج. تدخل الرسالة في سطر واحد في النمط التفاعلي؛
استخدم `--stdin` للنص متعدد الأسطر أو لتجنب ظهوره في معاملات العملية:

```sh
.venv/bin/python tools/chat.py --session draft ask --turn t1 --stdin
.venv/bin/python tools/chat.py --session draft history
```

أنه إدخال stdin بـCtrl-D. الأمر `ask` يطبع JSON، ورمز خروجه صفر
لجواب مكتمل، و1 لجواب مبتور أو خطأ محفوظ، و2 لرفض المدخل أو عطل
تشغيلي. الأمر `history` لا يتصل بالمزود. أسماء النماذج لا تظهر في
مخرج CLI المعتاد؛ بيانات التشغيل المحلية تحتوي الهوية والإعداد.

## الانقطاع وحدود السياق

تُطبع هوية الجولة قبل النداء. بعد Ctrl-C أو انقطاع العملية، أعد
الجولة نفسها بالنص نفسه عبر `ask --turn` لاسترجاع حالتها. إذا كانت
النتيجة محفوظة تُعاد دون نداء. إذا تعذر إثبات النتيجة تُعلن
`outcome_uncertain` أو `aborted_unclassified` بحسب موضع الانقطاع،
ولا يُعاد النداء آليًا؛ المحاولة الجديدة تحتاج
معرف جولة جديدًا تختاره صراحة. وقف العميل لا يضمن وقف حساب الخادم.

السياق يضم تعليمات النظام ثم أزواج الطلب والجواب المكتملة بالترتيب
ثم الطلب الحالي. الجواب المبتور والخطأ لا يدخلان في السياق اللاحق،
ويظهران في التاريخ. إذا تجاوز السياق الحد يرفض الطلب قبل النداء؛
لا تُحذف جولات قديمة صامتًا. الحد الافتراضي 24000 محرف، وهو حد
حمولة محلي لا قياس توكنات أو شهادة بفهم كل محتوى السياق.

لا تغير حالة جلسة من خارج الأداة ولا تنسخ ملفات بين جلستين. ملفات
`var/cli-chat/` خاصة بالحساب وخارج git، وتحفظ النصوص كما هي على القرص؛
ليست مشفرة. البيانات والسجل مبصومان، لكن مالك القرص يستطيع إعادة
كتابتهما أو إعادة نسخة قديمة معًا؛ لا تدعي البصمات منع هذا.

جلسات المحادثة ومساحة العمل لها جذور وعقود غرض مختلفة. تاريخ
`var/chat/` السابق يبقى في مكانه ولا يرحّل أو يعاد توليده تلقائيًا.
إذا كان معرفك موجودًا هناك، اقرأه صراحة بالأمر التالي أو اختر معرفًا
جديدًا للكتابة؛ يبقى إعداد المزود مطابقًا لإعداد الجلسة القديمة:

```sh
.venv/bin/python tools/chat.py --session daily --legacy-session history
```

هذه قراءة فقط؛ حتى checkpoint المعلق لا يُكتب من مسار العرض القديم.

## ما تفعله هذه النسخة

كل نداء يمر عبر `core.run.execute` بسياسة `local_only` وميزانية
مالية صفرية للمزود المحلي. بوابة م٩ تتحقق من هوية artifact المحلي
وتصد metadata التنفيذ البعيد وتستخدم عنوان loopback ثابتًا بلا
proxy أو redirects. هذا يفترض صدق الخادم المحلي؛ لا يعزل عملية
Ollama نفسها عن الشبكة على مستوى نظام التشغيل.

هذه النسخة لا تنفذ نص الجواب كأمر، ولا تتصل بأدوات أو مخازن المعرفة،
ولا تقرأ ملفات يذكرها المستخدم في المحادثة. تعليمات النظام تطلب
الصدق بشأن ذلك؛ منع التنفيذ تفرضه عدم إتاحة أدوات في عقد النداء،
أما صدق النص المولد فيحتاج مراجعة المستخدم.

## تحقق المطور

```sh
.venv/bin/python acceptance_m9.py
.venv/bin/python acceptance_m9.py --live --model "$DIWAN_CHAT_MODEL" \
  --model-version "$DIWAN_CHAT_DIGEST" --run-id local-first
```

التشغيل الافتراضي مصطنع صالح لـCI. التشغيل الحي يستهلك المزود
المثبت ويسجل الأجوبة خارج git؛ لا يثبت نجاح اختبار البنية جودة
المساعد أو قبول م٨ المستقل. راجع `M9-ACCEPTANCE.md` لنتيجة التنفيذ.

المزوّد يثبت نافذة تشغيل 32768 توكن وحد إخراج 4096 وحد مهلة
300 ثانية (الافتراضي 120). يرسل `truncate=false` و`shift=false`؛
دُعم الحقلان في [عقد ChatRequest للإصدار المحلي المفحوص](https://github.com/ollama/ollama/blob/v0.34.2/api/types.go)
وفي [معالج المحادثة نفسه](https://github.com/ollama/ollama/blob/v0.34.2/server/routes.go).
إصدارات الخادم الأخرى لم تُختبر بهذا الدليل. إذا رفض الخادم طول
السياق يظهر خطأ محفوظ؛ لا يعاد النداء بإعدادات أضعف صامتًا.
