# منسق الحفظ والنسيان الدائم — إثبات مصطنع

جزء من #269، وليس إغلاقًا لشروط ذاكرة الإنتاج. الوحدة
`webui/synthetic_lifecycle.py` مستقلة وغير موصولة بـ`Server` أو مدخل المتصفح.
لا تغيّر عقد `synthetic_only`، ولا تنشئ موافقة لنص المالك أو اعتماد Hub.

ينشئ المشغل `SyntheticLifecycle.create` بعقد إنشاء جديد وموافقته والهدف الثابت
وموصل التخزين وإعداد مزوّد مصطنع موثوق. لا تقبل الواجهة البرمجية كائن `LocalApp`
موجودًا أو مصنع تطبيق اختياريًا؛ ينشئه المنسق ويملكه داخليًا. أسماء السمات الخاصة
ليست عزلًا عن شيفرة المشغل نفسه: لا تنشر `_app` ولا تستعمله خارج المنسق. كل طلب
يدخل عبر `dispatch`، والحفظ الصريح عبر `save`، والإغلاق عبر `close`.

## الحالات

| الحالة | المسموح | الانتقال |
|---|---|---|
| `ready` | طلب واحد أو حفظ واحد تحت بوابة غير حاجزة | `saving` أو `closed` |
| `saving` | التطبيق مغلق؛ تصدير ثم التزام والتحقق والخروج من lease | `ready` بعد إعادة فتح سليمة، وإلا `blocked` |
| `blocked` | لا طلب أو حفظ أو إعادة فتح تلقائية | استعادة صريحة بكائن جديد وجذر جديد فقط |
| `closed` | لا طلب أو حفظ | استعادة صريحة بكائن جديد وجذر جديد فقط |

التوليد الحالي متزامن داخل `LocalApp.dispatch`، لكن خادم HTTP متعدد الخيوط.
تمنع بوابة المنسق دخول طلب ثانٍ أثناء الأول؛ ويفحص قبل الإغلاق كذلك `active`
و`active_agent_session` ويأخذ قفل `generation`. لذلك لا يعدّ رجوع طلب آخر أو
انقطاع عميله دليلًا على فراغ التوليد. إذا صار المزوّد مستقبلًا غير متزامن،
يجب أن يبقى حاملًا لقفل التوليد حتى انتهائه؛ لا يغلق المنسق ملفات توليد حي.

## النسيان

`dispatch(memory_forget)` يتحقق من السكون والعقد، ثم ينفذ النسيان المحلي تحت
بوابة الطلبات. لا يعيد نتيجته بعد. يغلق التطبيق، ويصدر لقطة فعلية عبر
`backup.export_workspace`، ويلتزم بها عبر `commit_synthetic_checkpoint` الذي
يتحقق من CAS/readback وتحرير lease. بعد إعادة فتح التطبيق بالعقد نفسه فقط
يرجع إيصال النسيان مع `durability.status=saved` وبصمة إيصال checkpoint.

الرد المكرر للنسيان المحلي يمر بالتثبيت الدائم نفسه، فلا يتحول وجود إيصال
محلي إلى دليل تخزين بعيد. رفض التوليد المشغول يقع قبل تعديل الذاكرة.
أما العطب بعد بدء النسيان أو الحفظ فيحجب المنسق: لا رد نجاح، ولا إعادة POST
تلقائية، ولا إعادة فتح أو فك قفل مشغول. قد يكون الرأس تقدم رغم فقد الرد؛
`cloud_forget_unconfirmed` و`cloud_checkpoint_unconfirmed` يعلنان عدم تأكيد
العملية، ولا يزعمان التراجع عنها. حتى فشل إعادة فتح التطبيق بعد نجاح الالتزام
لا يعرض نجاحًا للعميل.

`SyntheticLifecycle.restore` يقبل من المشغل عقدًا متوقعًا ووجهة غير موجودة
وإيصال سلف اختياريًا. تتم الاستعادة تحت lease وبأحدث سلطة نسيان؛ لا يُنشأ
`LocalApp` قبل نتيجة استعادة ناجحة وخروج lease. الجذر القديم لا يُتبنى ولا
يُعاد تصنيفه؛ النسخ والاعتمادات وأسماء المسارات ليست مدخلات متصفح.

## الدليل والحدود

اختبارات `tests/test_synthetic_lifecycle.py` تستعمل `LocalApp` ونسخ المنتج
الفعلية مع مزوّد ومخزن مصطنعين. تشمل حبس تحرير lease قبل إقرار النسيان،
واختبارات متزامنة للتوليد والحفظ، وأعطال قبل/بعد CAS وعند تحرير lease،
وتغيير العقد، وإغلاق التطبيق قبل التصدير، وفقد الجذر ثم استعادة سلف مع
غياب المنسي من طلبَي الجلسة النصية والوكيلة وبقاء غيره. طفراتها في
`tests/mutations/test_synthetic_lifecycle.jsonl`.

لا اختبار شبكة جديدًا أو دليل توفر/أداء أو حفظ كل رسالة في هذه الرقعة.
تظل شروط #269 الباقية: عقد وموافقة مستقلان لمحتوى المالك، واعتماد كتابة ضيق
لخزن خاص مخصص، وتوصيل واجهة مقيدة ومراجعة ذلك، ثم تجربة خدمة فعلية خاصة.
يبقى الاختبار السابق لإعادة تشغيل Space في
`docs/probe/hf-synthetic-session-restart-20261001.json` دليلًا على لقطة نسيان
محفوظة، ولا يُنسب إليه اختبار منسق هذه الرقعة أو جاهزية الإنتاج.
