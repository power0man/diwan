# عقد إنشاء مساحة سحابية خاصة مصطنعة — غير مفعّل إنتاجيًا

`workspace_tools/storage_scope.py` ينشئ عقد موافقة محليًا فقط. لا adapter أو شبكة
أو نشر أو نقل بيانات. لا يغير `DATA_POLICIES` ولا قرارات ق70/71 أو عتبات القياس.
كل مساحة وجلسة قائمة تبقى محلية بلا إعادة تصنيف أو تغيير بياناتها.

`internal` تصنيف الجلسات الجديدة منذ الميلاد، وليس وحده إذن رفع. موافقة التخزين
مستقلة، ولا تجيز النشر أو مزود استدلال بعيد. `ChatSession` و`AgentSession` يفحصان
عقد المزود المحلي القائم (الإعلان الصريح واسم نموذجه ومضيفه) واسم نموذج الطلب؛
الطلب والإيصال في المساحة الجديدة يحملان `internal` معًا، والقديمة `local_only`.

## واجهة المشغل الموثوق

1. `plan_cloud_workspace(target)` بلا وصول لملفات أو شبكة: يولد `workspace_id`
   و`namespace` عشوائيين، ويثبت `content_scope=synthetic_only` و
   `inference_policy=local_only`. الهدف المغلق هو
   `provider=huggingface_hub` و`repo_type/repo_id/branch`، ثم namespace المولد.
2. بعد عرض الخطة، `create_cloud_workspace(destination, plan,
   approval={"owner_approved": True, "plan_sha256": digest(plan)}, claims_root=authority)`.
   الموافقة bool صريح وبصمة الخطة كاملة، لا truthiness ولا موافقة لهدف آخر.
   `authority` دليل خاص موجود يملكه المشغل، والوجهة ابن مباشر جديد له.
   الموجود — حتى الفارغ والرابط الرمزي — مرفوض قبل الحجز.
3. حجز دائم بـ O_EXCL وfsync لكل target+namespace يسبق إنشاء الجذر؛ لا يُحذف عند
   الفشل أو حذف المساحة. علامة إنشاء خارجية تمنع فتح نتيجة مبتورة مساحةً محلية.
   لا تعاد المحاولة على namespace مستخدم ولا تنظيف تلقائي للحجوزات.
4. `.cloud-workspace.json` يحفظ الخطة والموافقة وبصمتهما؛ قراءة العقد لا تعدله.
   كل جلسة جديدة تربط هويتها ببصمة العقد. إعادة الفتح أو نسخ جلسة بين مساحتين
   لا يعيدان تصنيفها؛ الاختلاف أو فقد العقد يرفض. النسخ الاحتياطي والتحقق
   والاستعادة يحفظون العقد وربط الجلسات، ولا يقبلون جلسة محلية داخل العقد السحابي.

`LocalApp` يرفض هذا الجذر افتراضيًا. للاختبار فقط يطلب المشغل
`synthetic_cloud=True`؛ لا علم CLI ولا UI لإنشاء العقد أو تحويل مساحة قائمة.
رفع الملفات واستيراد المشروع والوسائط مغلقة في التجربة؛ وأي طلب يصرح بتصنيف
غير `internal` يرفض بدل إعادة تسميته. النص المصطنع مسؤولية مستدعي التجربة الموثوق؛
لا مصنف آلي يثبت أن نصًا بشريًا خالٍ من بيانات المالك.

## الحدود والتبعيات

- على المشغل استعمال سلطة إنشاء واحدة لكل هدف. الحجز يثبت عدم التكرار ضمن تلك
  السلطة، وليس سجلًا عالميًا. adapter لاحق يجب أن يطابق الهدف كاملًا، ويتحقق من
  الخصوصية ومن namespace فارغ فعلًا قبل أول حفظ. اسم repo لا يثبت خصوصيته.
- لا يتصل هذا العقد بنموذج اللقطات PR256؛ يظل رفضه `local_only` كما هو، وتظل
  الجلسات مرفوضة فيه حتى يضاف مسار قبول مستقل بعد المراجعة. لا السماح برفع أي
  `internal` غير مربوط بموافقة، ولا استثناء لحقل `local_only` داخل أرشيف.
- صلاحيات المضيف والمشغل موثوقة؛ البصمات ليست توقيع مالك أو دفاعًا ضد حسابه
  الذي يعيد كتابة العقد والجلسات معًا. لا وعد بحذف بايتات دفاتر التدقيق والنسخ القديمة.
- اختبارات `tests/test_cloud_workspace_scope.py` بمزود مصطنع فقط؛ لا استدلال
  حي أو ملفات مالك أو محجوب أو قياس متانة سحابية. لا تغيير لبوابة مراجعة العائلة.
