# مسار المحادثة والأدوات — قبول محدود في ٢٣ سبتمبر ٢٠٢٦

أصبح وضع «عمل بالأدوات داخل المشروع» يصل الواجهة بـAgentSession v2
ومخزن أفعال واحد. وضع النص والوسائط القديمان يبقيان قابلين لقراءة تاريخهما؛
لا يُحوّل تاريخ قديم إلى إذن جديد ولا إلى جلسة أدوات تلقائيًا.

## السلوك المثبت

- يرسل النقل `assistant.tool_calls` و`tool_call_id` كاملين. المزود النصي
  يرفض تاريخ الأدوات بدل إسقاطه. المزود المحلي يثبت نموذج Ollama وبصمته
  ويرفض المزود السحابي والوكيل الشبكي وإعادة التوجيه.
- تُحفظ نية نداء النموذج قبل بدئه، وخطة الأدوات قبل أول أثر. إعادة الجولة
  المكتملة تعرض السجل. نداء بدأ بلا نتيجة محفوظة يتوقف مجهول النتيجة؛
  لا توجد إعادة تلقائية له ولا وعد «تنفيذ مرة واحدة» عند كل انهيار ممكن.
- القرار يربط الفعل والجلسة والجولة والحجج ومواصفة الأداة ونسخة المدخلات
  وهوية مساحة العمل. معرف النداء وحده أو `owner_approved=True` لا يمنحان إذنًا.
- ملفات تنفيذ الأمر تُثبّت عند عرض القرار؛ التعديل أو إضافة ملف لاحقًا لا
  يغير البايتات الموافق عليها. الأمر يعمل داخل الحاوية المؤقتة المحددة بالإيصال.
- التحكم محفوظ خارج مساحة الأداة. تصل المرفقات المختارة وحدها بعد قبول
  الجولة والتحقق من بصماتها. بيانات الملف ليست سلطة تمنح أذونات.
- الرد المبتور أو المرفوض لا ينفّذ نداءات أدوات، سواء كان جديدًا أو معادًا.
  لكل جلسة حدود للسياق والجولات والخطوات، مع قفل للعملية والخيوط.
- الرجوع يستعمل مخزن الأفعال نفسه وطلبًا ثابت الهوية. يحافظ على تعديل
  المالك اللاحق، وإعادة طلب الرجوع تعرض إيصال العملية السابقة.
- التشغيل يعلن `local_edge` فقط؛ المستويات التي لم تُوصل لا تظهر كقدرة جاهزة.

## دليل القبول

[`probe/agent-runtime-20260923.json`](probe/agent-runtime-20260923.json)
يربط الأدلة ببصمات الشيفرة:

1. مجموعة macOS: 2907 ناجحة و4 متجاوزة قبل دمج أربعة اختبارات إسناد
   كانت ناجحة في دفعة CI السابقة. بوابة الدفع وCI يعيدان فحص الدفعة النهائية.
2. 33 فحصًا لسلوك JavaScript الفعلي في DOM مصطنع، تشمل الموافقة القديمة
   والخطأ واستعادة الاتصال وعرض النص دون تفسيره كـHTML. ليست دليل عرض متصفح.
3. تجربة متصفح حقيقي مستقلة: إنشاء مشروع وجلسة أدوات، كتابة ملف بمزوّد
   مصطنع، عرض الحجج وبصمة المدخلات، موافقة محددة، ناتج Docker حقيقي،
   إعادة تحميل الصفحة، ثم الرجوع والتحقق من غياب الملف.
4. نموذج Qwen3:14b فعلي عبر HTTP: كتابة نص محدد وقراءته، إعادة الجولة
   دون نداء جديد، الرجوع، ثم إعادة طلب الرجوع مع بقاء تعديل المالك الأحدث.
   نداءان للنموذج في هذه المهمة المحددة؛ لا يُستنتج منهما مستوى جودة عام.
5. ست تجارب Docker على منفذ التنفيذ المعدل: العزل، خروج كاذب في stdout،
   مهلة مع طفل، أمر مفقود، خروج ملتبس، وإيصال runtime غير مطابق.

المراجعة المستقلة كشفت سباقًا في تنظيف قفل الجلسة؛ أُثبت باختبار يفشل
على السلوك السابق ويمر بعد وضع قفل للخيوط قبل نشر مقبض الملفات.
كما أُغلق نسخ المرفقات قبل رفض الجولة. لا تُنسب هذه المراجعة إلى عائلتين
مختلفتين من النماذج؛ قبول الجودة المتعدد الأنظمة مسار مستقل لم يكتمل بعد.

## الاستخدام والحدود

تشغّل `tools/serve_ui.py` واجهة loopback. اختيار وضع الأدوات يتيح أدوات
ملفات المشروع؛ تشغيل الأوامر يحتاج `--runtime-receipt` من bootstrap
الموثوق خارج المشروع. عدم وجود الإيصال يخفي أدوات الأوامر ويعلن السبب.
ضبط الإيصال وحده لا يثبت نجاح Docker. لا تشغيل لأمر النموذج على المضيف.

لا يوجد بعد قبول كامل للبنك الجديد ذي 120 مهمة أو للرحلات التشغيلية
الثلاثين. المراجعة الآلية لا تغيّر أذونات الأفعال الخارجية. لا تنزيل
نموذج ولا استدعاء مدفوع ضمن هذا التسليم. لا ادعاء بعزل ثغرات Docker
VM/kernel أو مهاجم يملك حساب المضيف. لم يُنجز إلغاء نداء جارٍ أو اختبار
هاتف أو اعتماد شامل لإتاحة الوصول. جاهزية المنتج تبقى `false`.
