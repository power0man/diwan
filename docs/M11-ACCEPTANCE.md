# م١١ — واجهة العمل اليومية المحلية التجريبية

**٢١ سبتمبر ٢٠٢٦، ق٣٢.** المكون التقني أُنجز؛ اعتماد الاستخدام اليومي
والجودة البشرية باقيان. هذه البوابة تبني على ق٢٩ ولا تغلق م٨-ب.

## ما بُني

`tools/serve_ui.py` يشغل خادمًا مؤقتًا على `127.0.0.1`. واجهة عربية
باتجاه RTL تقدم مشروعات ومحادثات، رفع ملفات UTF-8 من اختيار المتصفح،
تفضيلات لكل مشروع، مدخلات الجواب المجمدة، ومراجعة/تطبيق مسودة إلى
ملف جديد. النموذج لا يملك API الواجهة؛ لا كتابة تلقائية من جوابه.
دليل المالك في `DAILY-UI.md`.

الخادم يعيد استعمال `ChatSession` و`AssistantWorkspace` و`Preferences`
و`TextWorkspace`، ويضيف `verified_outputs()` لفهرسة المرفقات ذات إيصال
كتابة مكتمل وبايتات مطابقة. الحالات غير المكتملة معلنة ومستبعدة من
الاختيار والإرسال؛ لا يتبنى ملفات بلا إيصالات.

المشروعات والجلسات تُهيأ في مجلد مرحلي ثم تظهر في الفهرس بإعادة تسمية
ذرية. تبقى بقايا التهيئة غير المكتملة خارج الفهرس للتشخيص، بحد 64؛
لا تُحذف تلقائيًا ولا يُتجاوز فساد بيانات مشروع منشور.

موافقة منسوبة إلى المالك.

## التدقيق العدائي والتفنيد

ثلاثة مدققين مستقلين: A للـHTTP والمهل والتزامن؛ B للمخزن والانقطاع
والعزل؛ C للواجهة والقبول. لكل عيب أدناه مفندان من العدستين الأخريين؛
تأكد الجميع، وأعيدت الحالات بعد الإصلاح.

| الرمز | السبب والأثر | الإغلاق |
|---|---|---|
| A1 | مهلة socket تقيس الخمول؛ تقطير الترويسات احتجز الاتصالات الثمانية ومنع الإغلاق | مهلة استقبال مطلقة للترويسات والجسم، تلغى قبل التوليد. أعيد الهجوم بمدته الحقيقية وباختبار قصير للـCI |
| B1 | HTTP 200 لنتيجة كتابة `error` جعل الواجهة تعلن إنشاء ملف قائم لم يُكتب | حالة HTTP فشل للكتابة المغلقة وفحص صريح لنتيجة العملية في الواجهة |
| B2 | رفع منقطع عاد ببيانات نجاح مع ملف فارغ، ثم عرض الفهرس ذلك الملف للاختيار | فحص نتيجة التطبيق وفهرس بالإيصالات المكتملة والبصمة والهوية؛ رفض المرفق الناقص قبل إنشاء المزود |
| B3 | إنشاء مجلد مشروع قبل بياناته سمح لانقطاع واحد بإخفاء بقية الفهرس | تهيئة خارج الفهرس ثم نشر ذري، ويشمل ذلك جلسة المحادثة الأولية |
| C1 | وصول جواب سابق محا مسودة أحدث كتبها المستخدم أثناء الانتظار | مسح حقل الرسالة فقط إذا بقي مطابقًا للنص المرسل |
| C2 | استجابة نافذة متأخرة فتحت مدخلات/تفضيلات/موافقة مشروع سابق أو أغلقت نافذة جديدة | ربط العرض وإكمال العمليات بهوية السياق ونسخة النافذة، بما فيه حفظ/حذف التفضيلات |
| C3 | استجابة إنشاء جلسة استخدمت المشروع الحالي المتغير بدل المشروع الأصلي | تثبيت المشروع عند الطلب وتجاهل إكمال التنقل المتأخر |

أُغلقت كذلك ضوضاء `BrokenPipe` المتوقعة عند انتهاء المهلة دون إسقاط
حفظ الجولة. اختبارات فقد اتصال العميل، النقر المتكرر، إعادة تشغيل
العملية بعد `pending`، وتعارض التفضيلات لا تستدعي المزود مرة أخرى.

التشغيل الأول لـCI كشف افتراضًا زائدًا في اختبار حد الاتصالات:
رفض الاتصال التاسع قد يظهر `BrokenPipeError` عند إرسال الجسم قبل
قراءة الاستجابة، أو يظهر انقطاعًا عند قراءتها. أضيف شكل الرفض الأول
إلى الاختبار بعد تفنيد مستقل؛ بقي شرط امتلاء الفتحات الثماني ورفض
الاتصال التاسع ثم تعافي الخادم كما هو، دون تغيير سلوك الخادم.

## حدود الإثبات

- نجحت طلبات HTTP وفحوص سلوك JS. طُلب عرض المعاينة المحلية بعد HTTP 200؛
  أعاد تطبيق Codex `queued`. لم يُفحص المتصفح بصريًا أو بقارئ شاشة.
- WebMCP الاختياري للقراءة فقط غير متحقق في سياق متصفح داعم؛ لا يعد
  وجود شيفرته أو نجاح اختبارات JS دليل تسجيله في المتصفح.
- لا حكم دلالي على الجواب أو مقاومة الحقن؛ `verification=unverified`.
- يحفظ الاسترجاع بايتات الحالة. قارئ سجل المحادثة الحالي قد يحدث
  `mtime`؛ فحص عدم تكرار تطبيق الملف يحفظ البايتات ووقت التعديل معًا.
- قياس الوقت الذي ينفقه حسين في المراجعة والتصحيح لم يحدث. البنك
  المستقل والمراجعة البشرية غائبان؛ `release_ready=false`.
- لا نشر عام، ولا خدمة دائمة، ولا تغيير حقوق المصادر أو إعداد هرمس.
  الصور والصوت وما يتطلبانه من قبول مستقل عمل المرحلة التالية.
